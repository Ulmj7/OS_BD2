8.1 Хэрэглэгчийн заавар

Хурдан эхлэх. make, дараа нь make test, дараа нь make run. Эцэст нь browser-ээр http://127.0.0.1:8080 хаягийг нээнэ.

8.1.1 Програмын зорилго

Энэ програм Linux кернелийн дугуй хоёр холбоост жагсаалт struct list_head-ийг турших зориулалттай. Үйлдэл бүрийн дараа next/prev заагч, kmalloc/kfree хэрхэн өөрчлөгдөхийг граф дээр харуулна.

Дөрвөн бүтэц бий: Өнгөний жагсаалт (номын Part I), Collatz (Part II), Стек, Дараалал. Графыг user-space-д ажилладаг C хөдөлгүүрийн жагсаалтын бодит заагчаас зурна. Хөдөлгүүр өөрийн list.h shim-ийг ашигладаг. Ачаалсан .ko модулийн жагсаалтыг үзэхэд dmesg ашиглана (8.2.7).

8.1.2 Дэмжих орчин

  • OS: Arch Linux дээр баг, Ubuntu/Xubuntu дээр шүүмжлэгчид туршсан. Хөдөлгүүр ба сервер POSIX орчинд ажиллах хэрэгсэл ашигладаг. Зөвхөн loopback тест /proc/net/tcp ба боломжтой бол /proc/net/tcp6-г уншина. macOS болон Windows-ийн үндсэн орчинд туршаагүй. Windows дээр Ubuntu/Xubuntu виртуал машин эсвэл WSL2-г ашиглана (8.2.2–8.2.3).
  • Хэрэгсэл: gcc (16.2.1-ээр туршсан), make (GNU Make 4.4.1), python3 (3.14.8; зөвхөн стандарт сан).
  • Browser: JavaScript ба SVG дэмждэг орчин үеийн browser (Brave 158/Chromium дээр туршсан). Интернет холболт шаардахгүй.

8.1.3 Суулгах, нээх алхам

  1. Репозиторийг GitHub-ээс 8.2.1 дэх командаар татна. Холболтгүй бол хүргэсэн хавтсыг хуулж, тэр хавтас руу cd хийнэ.
  2. Бүтээх: make. build/kds_engine үүснэ.
  3. Шалгах (заавал биш): make test. Эцэст нь All available tests passed. гарна.
  4. Асаах: make run. Терминалд http://127.0.0.1:8080 гарна.
  5. Browser-ээр энэ хаягийг нээнэ. Дээд талд «Хөдөлгүүр холбогдсон» гэж харагдвал бэлэн.

Бэлэн жишээ: «Номын 4 өнгө» (color example) ба «Collatz · 27-оос эхлэх».

Командыг шууд оруулах хэсэгт дурын хөдөлгүүрийн команд бичиж болно (жишээ нь inject_fail after=2, check). Нэг мөр, ≤ 512 тэмдэгт.

URL параметр: ?run=cmd1;cmd2 (командуудыг дарааллаар автоматаар ажиллуулна), ?tab=color|collatz|stack|queue, ?theme=dark.

8.1.5 Ажиллуулах, зогсоох, reset хийх

  • Ажиллуулах: make run. Үйлдэл хийхдээ «Үйлдлийг гүйцэтгэх» товчийг (эсвэл Enter) дарна.
  • Зогсоох: make run-ийн терминал дээр Ctrl+C. Хөдөлгүүр дуусахдаа чөлөөлөөгүй санах ой үлдсэн бол LEAK: live=N гэж бичнэ. Хэвийн үед энэ гарахгүй.
  • Reset: «Бүх бүтцийг хоослох» товч (reset) 4 бүтцийг чөлөөлж, алдааны тарилгыг унтраана. kmalloc/kfree-ийн хуримтлагдсан тоолуур үргэлжилнэ.
  • Хөдөлгүүрийг бүрэн дахин эхлүүлэх: сервер зогсоож дахин асаана, эсвэл curl -X POST http://127.0.0.1:8080/api/restart.
  • Түүх: «Үйлдлийн түүх» дэх ← → товч, гулсуур, «Сүүлийн алхам». Өнгөрсөн алхам зөвхөн уншигдана, үйлдэл түгжигдэнэ. Түүх browser-ийн табд хадгалагдана; хуудсыг дахин ачаалбал алга болно. Бүтцүүд хөдөлгүүрт хэвээр үлдэнэ.
  • Анхаар: ?run=…-тай хуудсыг дахин ачаалбал командууд дахин ажиллана.

8.1.7 Жишээнүүд

Жишээ 1 — Номын Part I: 4 өнгө, хайх, устгах

  1. Өнгөний жагсаалт таб → «Номын 4 өнгө». Хүлээгдэх үр дүн: 4 зангилаа. dmesg хэсэгт: 
    color[0]: red=138, green=43, blue=226
color[1]: red=255, green=0, blue=0
color[2]: red=0, green=255, blue=0
color[3]: red=0, green=0, blue=255
    Санах ой (дөнгөж асаасан хөдөлгүүр дээр): kmalloc 4, kfree 0, амьд 4, 128 байт. Эхний зангилаа нь violet (138, 43, 226).
  2. «Өнгөөр хайх», red = 255. «Олдсон» тодорно: #2 (индекс 1). Хайлтын зам #1 → #2 анимацитай.
  3. «Индексээр устгах», index = 1. list_del(&#2->list), kfree(#2) болж, граф #1 → #3 → #4 болно. Тоолуур: kmalloc 4 / kfree 1 / амьд 3 / 96 байт.
  4. «Бүх бүтцийг хоослох». Амьд зангилаа 0 болно.

Жишээ 2 — Part II: Collatz дараалал, хайх, алдаа

  1. Collatz таб → «Дараалал үүсгэх», start = 27. Хүлээгдэх үр дүн: 112 зангилаа, 111 алхам, оргил 9232; 27 → 82 → 41 → 124 → 62 → 31 → … Амьд зангилаа 112 (24 B × 112 = 2,688 байт).
  2. «Утгаар хайх», value = 9232. Хайлт эхнээс явж 77-р индексэд (оргил) олдоно.
  3. Алдааны шалгалт. «Командыг шууд оруулах» хэсэгт collatz run start=0 гэж бичиж илгээнэ. Энэ нь форм биш: «Дараалал үүсгэх» формын start талбар min=1 тул browser 0-г өөрөө хаадаг бөгөөд engine хүртэл хүрэхгүй. Улаан мөр E_RANGE гарна. Граф (112 зангилаа) болон тоолуур өөрчлөгдөхгүй.
  4. «Утгаар устгах», value = 9232. 111 зангилаа үлдэнэ.
  5. «Дараалал үүсгэх», start = 837799. 525 зангилаа, оргил 2974984576 (int32-ээс их, тиймээс 64 бит).

Жишээ 3 — Стек (LIFO) ба дараалал (FIFO)

Стек: push 10, push 42, push −2. TOP = −2 болно. pop хийвэл −2 гарч, TOP = 42 болно.

Дараалал: enqueue 10, enqueue 42. FRONT = 10, REAR = 42 болно. dequeue хийвэл 10 гарна.

Жишээ 4 — Командыг URL-ээр ажиллуулах

http://127.0.0.1:8080/?run=reset;color%20example;color%20delete%20index=1 — reset хийгээд номын жишээг үүсгэж, 1-р индексийг устгана.

Жишээ 5 — ENOMEM тарилга

«Командыг шууд оруулах» хэсэгт inject_fail after=2 гэж бичнэ. Дараа нь color add_tail red=1 green=2 blue=3-ийг гурав гүйцэтгэнэ. Эхний хоёр нь амжилттай. Гурав дахь нь E_NOMEM («kmalloc failed; the previous state is preserved») өгч, граф өөрчлөгдөхгүй. inject_fail off тарилгыг унтраана.

UI-г виртуал машины browser-оор нээнэ. Зөвхөн user-space хэсгийг ажиллуулах бол PowerShell-ээс wsl --install -d Ubuntu ажиллуулаад Ubuntu терминалд C хэрэгсэл, Python-оо суулгана. WSL2-ийн өөрийн кернелийн таарах header ердийн Ubuntu сангаас олдохгүй байж болох тул make module болон insmod-д виртуал машин ашиглана.

8.2.3 Хэрэгсэл суулгах

Гуравдагч талын сан шаардахгүй. Хэрэгсэл байхгүй бол дараах командыг ашиглана (жишээ; энд ажиллуулаагүй):

# Arch Linux
sudo pacman -S base-devel python linux-headers git
# Debian / Ubuntu (Xubuntu орно)
sudo apt update
sudo apt install build-essential python3 linux-headers-$(uname -r) git

Зөвхөн user-space ажиллуулах бол linux-headers багц шаардлагагүй. Кернел модуль бүтээхэд (заавал биш, 8.2.7) ажиллаж буй кернелтэй ижил хувилбарын header хэрэгтэй. Arch дээр linux-headers, Debian/Ubuntu дээр linux-headers-$(uname -r) багц. Багийн гишүүн Arch дээр pacman-аар суулгасан: linux ба linux-headers хоёулаа 7.2.11.arch1-1.

8.2.4 Build ба Run командууд

КомандҮр дүн
makebuild/kds_engine, build/libkds.a (shim + engine core)
make test / make test-userUser-space C, protocol, HTTP тест (build/sanitized/ дахь ASan+UBSan build-ээр). Алдаатай бол 0-ээс өөр кодтой гарна. SIGINT (Ctrl+C) үл тоомсорлогдсон орчинд (жишээ нь nohup, CI) ч ажиллана.

make module KDIR=…Жинхэнэ кернел модуль (Kbuild) src/kernel/*.ko. Кернелийн header шаардана (8.2.7). KDIR заагаагүй бол /lib/modules/$(uname -r)/build ашиглана.
make cleanbuild/, кэш болон кернелийн build үлдэгдлийг устгана. Анхаар: src/kernel/*.ko файлуудыг мөн устгана.

Хөдөлгүүрийг шууд (UI-гүй) ажиллуулж болно. Нэг команд = нэг мөр, хариу = нэг мөр JSON:

printf 'color example\ncolor delete index=1\nstate\n' | build/kds_engine
build/kds_engine --max-nodes 3 < tests/cases/max_nodes.in

8.2.5 Үндсэн тестийн өгөгдөл

Программын ажиллагааг шалгахын тулд холбоост жагсаалт, кернел модуль, хөдөлгүүр, HTTP сервер болон веб интерфэйсийн тестүүдийг тус тусад нь боловсруулсан. Тестийн файлууд болон тэдгээрийн шалгах зүйлсийг дараах хүснэгтэд нэгтгэв.

Файл Тестийн агуулга
tests/test_list.c Өөрсдийн хэрэгжүүлсэн list.h файлын үндсэн үйлдлүүдийг шалгана. Мөн 5,000 санамсаргүй үйлдлээр туршина (seed 0x0c011a72).
tests/test_color_module.c, test_collatz_module.c Кернел модулиудын эх кодыг shim орчинд ажиллуулж, логийн гаралт, санах ойн алдагдал болон ENOMEM алдаатай нөхцөлийг шалгана. Collatz дарааллыг 1, 15, 25, 27, 97, 837799, 2147483647 гэсэн утгуудаар туршина.

tests/run_cases.py Урьдчилан бэлтгэсэн сценарийн командуудыг ажиллуулж, гаралтыг хүлээгдэж буй JSON үр дүнтэй харьцуулна.
tests/test_server.py HTTP серверийн 15 тестийг агуулна. SIGINT дохионы хоёр нөхцөлд сервер зөв унтарч байгаа эсэх, хэт том хүсэлт, зөвшөөрөгдөөгүй Host болон 100 зэрэгцээ POST хүсэлтийг шалгана. tcp6 файл байхгүй үед IPv4 холболтыг шалгана.
tests/ui/browser_check.py, tests/ui/interactions.py Brave болон Chromium хөтөч дээр веб интерфэйсийн ажиллагааг CDP ашиглан шалгана. Эдгээр нь нэмэлт тест бөгөөд make test командад ороогүй.
tests/README.md Тест бүрийн оролт, хүлээгдэж буй үр дүн болон тухайн үр дүнг хэрхэн тодорхойлсон талаарх мэдээллийг агуулна.

Веб интерфэйсийн нэмэлт шалгалт

Веб интерфэйсийн тестээр дөрвөн табын ажиллагаа, 112 зангилаа болон 226 сумны дүрслэл, үйлдэл хийх форм, «Бүгдийг багтаах» горим, End товчлуурын ажиллагааг шалгасан.

Мөн 320 болон 390 пикселийн өргөнтэй дэлгэц дээр интерфэйс хэрхэн харагдаж байгааг шалгахад JavaScript-ийн алдаа гараагүй. Brave 158 дээр тоон утга оруулах хэсэгт abc гэсэн буруу оролтыг хориглож, -5, +7, 42 гэсэн утгуудыг зөвшөөрч байгааг туршсан.

UI тестийг ажиллуулахын тулд эхний терминалд серверийг асаана.

make run

Дараа нь өөр терминал нээж дараах хоёр командыг ажиллуулна.

python3 tests/ui/browser_check.py
python3 tests/ui/interactions.py

Тестийн явцад скриптүүд хөдөлгүүрийг дахин эхлүүлж, жагсаалтын төлөвийг өөрчилдөг. Туршилтын үеэр авсан дэлгэцийн зургууд /tmp/kds-ui-check хавтаст хадгалагдана.

Шаардлагатай тохиолдолд дараах орчны хувьсагчийг тохируулж болно.

Хувьсагч Зориулалт

KDS_BROWSER Хөтчийн ажиллуулах файлын замыг заах

Эдгээр скрипт нь график цонх нээхгүйгээр хөтчийг headless горимоор ажиллуулдаг. --no-sandbox тохиргоо ашигладаг тул зөвхөн итгэмжит локал веб интерфэйс дээр ажиллуулах зориулалттай.

Collatz лавлагааг дахин үүсгэх

Collatz дарааллын зөв үр дүнг төслийн үндсэн кодоос хамааралгүйгээр Python дээр тооцоолсон. Лавлагааны утгуудыг дахин үүсгэх шаардлагатай бол дараах командыг ажиллуулна.

python3 tests/reference_cases.py

8.2.6 Захын утга болон алдаатай нөхцөлийн нэмэлт тест

Программ зөв оролт дээр ажиллахаас гадна хэрэглэгч буруу утга оруулах үед хэрхэн ажиллаж байгааг шалгасан. Үүнд зөвшөөрөгдөх хэмжээнээс хэтэрсэн тоо, дутуу параметр, буруу команд, хоосон жагсаалт болон санах ой хуваарилах боломжгүй нөхцөлүүд багтсан.

Хөдөлгүүрийн түвшний шалгалт

Хөдөлгүүрийг веб интерфэйс ашиглахгүйгээр терминалаас шууд шалгах боломжтой.

Жишээлбэл:

printf 'collatz run start=0\n' | build/kds_engine

Алдаатай команд ажиллуулах үед JSON гаралтад "ok":false гэсэн утга болон тухайн алдаанд харгалзах error.code гарна. Алдаа гарсан команд жагсаалтын төлөвийг өөрчлөхгүй.

Команд болон нөхцөл Хүлээгдэж буй алдааны код

color add_tail red=1 green=2 blue=3 alpha=4 E_UNKNOWN_ARG

HTTP серверийн түвшний шалгалт

Сервер зөв хүсэлт хүлээн авахаас гадна буруу бүтэцтэй болон зөвшөөрөгдөөгүй хүсэлтийг хэрхэн боловсруулж байгааг curl командаар шалгасан.

Дараах командуудыг сервер ажиллаж байх үед гүйцэтгэнэ. Доор дурдсан HTTP статусуудыг бодитоор туршиж баталгаажуулсан.

Эхлээд серверийн хаягийг хувьсагчид хадгална.

U=http://127.0.0.1:8080

Зөв бүтэцтэй хүсэлт илгээх:

curl -s -X POST -H 'Content-Type: application/json' \
-d '{"cmd":"color example"}' $U/api/cmd

Хүлээгдэж буй үр дүн: HTTP 200, "ok":true.

Content-Type буруу байх үед:

curl -s -X POST -H 'Content-Type: text/plain' \
-d '{"cmd":"state"}' $U/api/cmd

Хүлээгдэж буй үр дүн: HTTP 400, E_SYNTAX.

Буруу бүтэцтэй JSON илгээх:

curl -s -X POST -H 'Content-Type: application/json' \
-d '{bad' $U/api/cmd

Хүлээгдэж буй үр дүн: HTTP 400, E_SYNTAX.

Нэг хүсэлтээр олон мөртэй команд илгээх:

curl -s -X POST -H 'Content-Type: application/json' \
-d '{"cmd":"state\nreset"}' $U/api/cmd

Хүлээгдэж буй үр дүн: HTTP 400. Сервер зөвхөн нэг мөртэй команд хүлээн авна.

Зөвшөөрөгдөөгүй Origin-оос хүсэлт илгээх:

curl -s -X POST -H 'Origin: http://evil.example' \
-H 'Content-Type: application/json' \
-d '{"cmd":"state"}' $U/api/cmd

Хүлээгдэж буй үр дүн: HTTP 403, E_ORIGIN.

Өөр Host ашиглан хандах:

curl -s -H 'Host: example.invalid' $U/api/state

Хүлээгдэж буй үр дүн: HTTP 403, E_ORIGIN.

Веб серверийн үндсэн хавтсаас гаднах файлд хандах:

curl -s --path-as-is -o /dev/null \
-w '%{http_code}\n' "$U/../Makefile"

Хүлээгдэж буй үр дүн: HTTP 403.

Байхгүй файлд хандах:

curl -s -o /dev/null \
-w '%{http_code}\n' $U/nonexistent.js

Хүлээгдэж буй үр дүн: HTTP 404.

Хөдөлгүүрийг дахин эхлүүлэх:

curl -s -X POST $U/api/restart

Хүлээгдэж буй үр дүн: HTTP 200. Хөдөлгүүр дахин эхэлж, бүх өгөгдлийн бүтэц хоосон төлөвт шилжинэ.

Эдгээр шалгалтаар сервер буруу хүсэлтийг зохих алдааны мэдээлэлтэйгээр буцааж, зөвшөөрөгдөөгүй хандалтыг хориглож байгаа эсэхийг шалгасан.

8.2.7 Бодит кернел модулийг хөрвүүлэх, ачаалах, буулгах

Шинэчилсэн кернел модулиудыг 2026 оны 11-р сарын 25-нд Arch Linux 7.3.4-arch1-2 (x86_64) орчинд хөрвүүлж, хоёр удаа ачаалж буулган туршсан. Өмнөх хувилбарыг Arch Linux, Ubuntu болон Xubuntu дээр ажиллуулсан үр дүн, мөн Ubuntu sandbox орчинд хөрвүүлсэн талаарх мэдээллийг тайлангийн 8.7–8.9-р хэсгээс харах боломжтой.

Анхаарах зүйл

Кернел модуль нь үйлдлийн системийн кернелд шууд ачаалагдаж ажилладаг тул кодод алдаа байвал систем гацах эрсдэлтэй. Иймээс туршилт хийхээс өмнө нээлттэй ажлуудаа хадгалах, боломжтой бол виртуал машин ашиглахыг зөвлөж байна.

Мөн Secure Boot идэвхтэй эсвэл модулийн гарын үсэг шаарддаг системд гарын үсэггүй модуль ачаалагдахгүй байж болно. Манай баг энэ нөхцөлийг тусгайлан шалгаагүй бөгөөд туршилт хийсэн компьютер дээр модулиуд хэвийн ачаалагдсан.

1. Кернелийн header суулгах

Кернел модулийг хөрвүүлэхэд тухайн компьютер дээр ажиллаж буй кернелийн хувилбарт тохирсон header файл шаардлагатай.

Arch Linux дээр дараах командаар суулгана.

sudo pacman -S linux-headers

Одоо ашиглаж буй кернелийн хувилбарыг шалгана.

uname -r

Дараах командаар шаардлагатай header файлууд байгаа эсэхийг шалгана.

ls /usr/lib/modules/$(uname -r)/build

Хэрэв тохирох header суусан бол build замд хандах боломжтой байна.

2. Кернел модулиудыг хөрвүүлэх

Төслийн үндсэн хавтсаас дараах командыг ажиллуулна.

make module KDIR=/usr/lib/modules/$(uname -r)/build

Хөрвүүлэлт амжилттай явагдах үед CC [M], MODPOST, LD [M] зэрэг мэдээлэл терминалд гарна. BTF мэдээлэл үүсгэх боломжтой орчинд BTF [M] гэсэн мөр мөн гарч болно.

Xubuntu дээр турших үед vmlinux файл байхгүйгээс BTF мэдээллийг алгассан болон хөрвүүлэгчийн хувилбарын мэдээлэл зөрүүтэй гэсэн мэдэгдлүүд гарсан. Гэхдээ эдгээр нь хөрвүүлэлтийг зогсоогоогүй бөгөөд хоёр .ko файл амжилттай үүсэж, кернелд ачаалагдсан.

Хөрвүүлэлт дууссаны дараа src/kernel/ хавтаст дараах хоёр файл үүссэн эсэхийг шалгана.

color_list.ko
collatz.ko

Файлын хэмжээ нь ашигласан хөрвүүлэгч, кернелийн хувилбар болон хөрвүүлсэн замаас хамааран өөр байж болно.

Модулийн мэдээллийг дараах командаар харна.

modinfo src/kernel/color_list.ko
modinfo src/kernel/collatz.ko

Гаралтаас лиценз нь GPL болохыг, vermagic хэсгээс ямар кернелийн хувилбарт зориулан хөрвүүлснийг харж болно. Collatz модульд бүхэл тоон төрлийн start параметр байгаа нь мөн харагдана.

3. Part I: Өнгөний жагсаалтын модулийг ажиллуулах

Эхний модуль нь дөрвөн өнгөний RGB утгыг хоёр чиглэлт холбоост жагсаалтад хадгалдаг.

Модулийг кернелд ачаалах:

sudo insmod src/kernel/color_list.ko

Кернелийн логийг харах:

sudo dmesg | tail -20

Модуль зөв ажилласан бол дараах дөрвөн мөр гарна.

color[0]: red=138, green=43, blue=226
color[1]: red=255, green=0, blue=0
color[2]: red=0, green=255, blue=0
color[3]: red=0, green=0, blue=255

Жагсаалтын эхний элемент нь violet өнгө бөгөөд үлдсэн элементүүд нь улаан, ногоон, цэнхэр өнгийг илэрхийлнэ.

Шалгалт дууссаны дараа модулийг кернелээс буулгана.

sudo rmmod color_list

Модулийг буулгах үед жагсаалтын дөрвөн зангилааг устгаж, тэдгээрт хуваарилсан санах ойг чөлөөлнө.

4. Part II: Collatz модулийг ажиллуулах

Хоёр дахь модуль нь өгөгдсөн эерэг бүхэл тооноос эхлэн Collatz дарааллыг үүсгэж, утга бүрийг холбоост жагсаалтад хадгалдаг.

Энэ удаагийн туршилтаар дарааллыг 27-оос эхлүүлнэ.

sudo insmod src/kernel/collatz.ko start=27

Үүссэн дарааллыг кернелийн логоос харна.

sudo dmesg | tail -130

Collatz дарааллыг 27-оос эхлүүлэхэд нийт 112 утга үүсдэг. Индекс нь 0-ээс 111 хүртэл үргэлжлэх бөгөөд дарааллын эхний утгууд 27, 82, 41, 124 байна. Харин 77-р индекс дээр 9232 гэсэн хамгийн их утгад хүрч, эцэст нь 4, 2, 1 гэсэн утгуудаар дуусна.

Логийн зарим мөрийг жишээ болгон үзүүлбэл:

collatz[0]: value=27
collatz[1]: value=82
...
collatz[77]: value=9232
...
collatz[111]: value=1

Бүх 112 мөрийг харахын тулд tail -130 ашигласан. Иймээс өмнөх кернелийн логийн зарим мөр хамт гарч болно.

Шалгалт дууссаны дараа модулийг буулгана.

sudo rmmod collatz

5. Модулиудыг зөв буулгасан эсэхийг шалгах

Хоёр модулийг буулгасны дараа дараах командыг ажиллуулна.

lsmod | grep -E 'color_list|collatz'

Хэрэв ямар нэг мэдээлэл гарахгүй байвал хоёр модуль кернелд ачаалагдсан хэвээр үлдээгүй гэсэн үг.

Туршилтын явцад insmod болон rmmod командууд алдаагүй ажилласан.

Collatz-ийн бусад эхлэх утгыг шалгасан үр дүн

II-4-1 баг төслийн өмнөх хувилбарыг Ubuntu дээр ажиллуулахдаа start параметр өгөөгүй үед дараалал анхдагч 25 гэсэн утгаас эхэлж, 24 мөр үүсгэж байгааг баталгаажуулсан.

Мөн start=0 гэсэн буруу утга өгөхөд insmod команд Invalid parameters алдаа буцааж, кернелийн логт дараах мэдээлэл гарсан.

collatz: start must be positive

Харин шинэчилсэн хувилбар дээр 25 болон 0 гэсэн утгуудыг бодит кернелд дахин туршаагүй. start=15 үед 18 мөр үүсэхийг shim орчны тестээр шалгасан.

Модулийг буулгах үеийн санах ойн бүртгэл

Бодит кернел дээр хийсэн хоёр удаагийн туршилтаар модулиудыг insmod командаар ачаалж, rmmod командаар алдаагүй буулгасан.

Үүний дараа кернелийн логийг дараах командаар шалгасан.

sudo dmesg | grep -E 'color|collatz'

Туршилтын орчин: Arch Linux 7.3.4-arch1-2, 2026.11.25

Модуль Кернелийн логийн үр дүн
color_list Өнгөний дөрвөн мөр хэвлэгдэж, модулийг буулгасны дараа color_list: freed 4 nodes гэсэн мэдээлэл гарсан.
collatz start=27 Нийт 112 утга хэвлэгдэж, 77-р индекс дээр 9232 гэсэн хамгийн их утгад хүрсэн. Модулийг буулгахад collatz: freed 112 nodes гэсэн мэдээлэл гарсан.

Мөн shim орчинд модулийн анхны тохиргоо амжилтгүй болсон нөхцөлийг тусад нь шалгасан. Энэ үед exit функцийг дуудахад freed 0 nodes гэсэн мэдээлэл гардаг.

Кернелийн эдгээр лог нь модуль өөрийн жагсаалтаас хэдэн зангилаа чөлөөлснийг харуулж байгаа боловч дангаараа кернелийн санах ойн алдагдал байхгүйг бүрэн батлах хэмжилт биш юм.

8.2.8 make test командын хүлээгдэж буй үр дүн

Төслийн автомат тестүүдийг ажиллуулахын тулд үндсэн хавтсаас дараах командыг өгнө.

make clean && make && make test

Энэ команд нь өмнөх хөрвүүлэлтээр үүссэн файлуудыг устгаж, программыг дахин хөрвүүлсний дараа автомат тестүүдийг ажиллуулна.

Эцсийн хувилбар дээр уг командыг ASan болон UBSan ашиглан таван удаа дараалан ажиллуулсан бөгөөд бүх удаад exit code 0-тэй амжилттай дууссан. HTTP серверийн тестийг мөн 30 удаа дараалан ажиллуулахад алдаа гараагүй.

Дараах команд нь ижил тестийн багцыг ажиллуулна.

make test-user

Бүх тест амжилттай дууссан үед гаралтын үндсэн мэдээлэл дараах байдалтай байна.

Дээрх үр дүнгээс Collatz болон өнгөний модулиуд, холбоост жагсаалтын үндсэн үйлдлүүд, алдаатай нөхцөлүүд, хөдөлгүүрийн командууд болон HTTP серверийн тестүүд амжилттай ажилласныг харж болно.

Тест ажиллах хугацаа болон санах ойн хаяг нь компьютер бүрд өөр байж болно.

make test команд нь кернелийн header файл шаардахгүй бөгөөд модулийг бодит кернелд ачаалахгүй. Учир нь эдгээр автомат тест нь хэрэглэгчийн буюу user-space shim орчинд ажилладаг.

8.2.9 Мэдэгдэж буй хязгаарлалт

Төслийн үндсэн ажиллагааг хэрэгжүүлж, олон төрлийн тестээр шалгасан боловч одоогийн хувилбарт дараах хязгаарлалтууд бий.

Кернелийн санах ойн шалгалт

Shim орчинд ASan болон kmalloc, kfree функцийн дуудалтын тоог ашиглан санах ойн алдагдал байгаа эсэхийг шалгасан. Туршсан нөхцөлүүдэд санах ойн алдагдал илрээгүй.

Гэхдээ бодит кернел дээр kmemleak, slabinfo ашиглан санах ойг хэмжих, модулийг 200 удаа дараалан ачаалж буулгах болон ENOMEM алдаатай нөхцөлийг шалгах туршилтуудыг хийгээгүй.

Мөн Collatz модулийн анхдагч start=25 болон буруу start=0 утгыг шинэчилсэн хувилбараар бодит кернелд дахин туршаагүй. Кернелийн туршилтын дэлгэрэнгүй үр дүнг тайлангийн 8.8–8.9-р хэсгээс харах боломжтой.

Shim орчны хязгаарлалт

Shim нь кернелийн зарим функцийг хэрэглэгчийн орчинд ажиллуулах боломж олгодог боловч бодит кернелийн ажиллагааг бүхэлд нь орлохгүй. Тухайлбал, GFP флагуудын ажиллагаа, олон процессорын зэрэгцээ ажиллагаа (SMP) болон санах ойн бодит дарамтыг загварчлаагүй.

Тестийн үеэр ENOMEM алдааг зориудаар үүсгэсэн бөгөөд энэ нь системийн санах ой бодитоор дууссан нөхцөлөөс ялгаатай.

Сүлжээний тест

IPv6 дэмждэггүй системд /proc/net/tcp6 файл байхгүй байж болно. Ийм үед loopback тест нь уг файлыг алгасаж, зөвхөн IPv4 холболтыг шалгана.

Хэрэв /proc/net/tcp файл мөн байхгүй бол зөвхөн socket хүснэгтийг шалгах тестийг алгасана.

Серверийн порт

make run командаар серверийг ажиллуулах үед 8080 портыг ашигладаг. Хэрэв өөр порт ашиглах шаардлагатай бол серверийг шууд ажиллуулж, портын тохиргоог өөрчлөх боломжтой. Үүнийг 8.1.4-р хэсэгт тайлбарласан.

8080 портыг өөр программ ашиглаж байгаа үед Python-ийн алдааны мэдээлэл буюу traceback гарна.

Веб хөтчийн дэмжлэг

Манай баг веб интерфэйсийн автомат шалгалтыг Brave болон Chromium хөтөч дээр хийсэн. Мөн II-4-1 баг Firefox 147 дээр интерфэйсийг ажиллуулж шалгасан.

tests/ui/browser_check.py болон tests/ui/interactions.py скриптүүд нь нэмэлт тест тул make test командаар автоматаар ажиллахгүй. Эдгээрийг ажиллуулахын тулд Brave эсвэл Chromium хөтөч суулгасан байх шаардлагатай.

Collatz дарааллын элемент устгах үйлдэл

collatz delete командаар дарааллын дурын зангилааг устгах боломжтой. Ингэснээр үлдсэн утгууд Collatz дарааллын математик дүрэмд нийцэхгүй болж болно.

Энэ үйлдлийг Collatz дарааллыг шинээр тооцоолох бус, холбоост жагсаалтаас элемент устгахад холбоосууд хэрхэн өөрчлөгдөж байгааг харуулах зорилгоор оруулсан.

Санах ойн бүртгэлийн дугаар

Зарим команд амжилтгүй болохоосоо өмнө түр хугацаанд санах ой хуваарилж болно. Алдаа гарвал тухайн санах ойг буцаан чөлөөлдөг боловч kmalloc бүртгэлийн дугаарт (#) алгассан дугаар харагдаж болно.

Энэ нь заавал санах ойн алдагдал гарсан гэсэн үг биш юм.

Олон хэрэглэгчийн дэмжлэг

HTTP серверийг зөвхөн тухайн компьютер дээр ажиллуулах зориулалтаар хийсэн бөгөөд 127.0.0.1 хаягаар хандана. Одоогийн хувилбар нь олон хэрэглэгч зэрэг ашиглах зориулалттай систем биш.

Урт жагсаалтын дүрслэл

Олон зангилаатай жагсаалтыг «Бүгдийг багтаах» горимоор дэлгэцэд бүхэлд нь харж болно. Гэхдээ зангилааны тоо ихсэх тусам бичиг болон дүрслэлийн хэмжээ жижигэрч, уншихад хүндрэлтэй болдог.

Ийм үед графыг томруулах эсвэл хүснэгтээр мэдээллийг харах боломжтой. Одоогоор зангилаануудыг бүлэглэж, хураангуй хэлбэрээр харуулах боломж байхгүй.

Сессийн санах ойн тоолуур

kmalloc болон kfree тоолуур нь хөдөлгүүр ажиллаж эхэлснээс хойших нийт дуудалтын тоог харуулдаг.

Веб хуудсыг дахин ачаалах болон reset команд ажиллуулах үед өмнөх хуримтлагдсан тоо хэвээр үргэлжилнэ. Одоогийн хувилбарт хэрэглэгчийн сесс бүрийн санах ойн тоолуурыг тусад нь харуулах боломж байхгүй.
