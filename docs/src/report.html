Хураангуй

Асуудал. Сурах бичгийн 3-р бүлгийн 4-р төсөл нь кернелийн дугуй хоёр холбоост жагсаалтыг ашиглан өнгөний жагсаалт болон Collatz дарааллыг хадгалуулахыг шаарддаг. Багшийн даалгаврын дагуу үйлдэл бүрийн дараа жагсаалтын бүтэц хэрхэн өөрчлөгдөхийг график дээр харуулах ёстой.

Шийдэл. Модулийн жинхэнэ эх кодыг өөрчлөхгүйгээр хоёр аргаар шалгасан. Нэгдүгээрт, кернелийн функцийг дуурайдаг өөрсдийн жижиг давхарга («shim») дээр энгийн программ болгон ажиллуулсан. Хоёрдугаарт, ажиллаж буй кернелийн жинхэнэ header-тэй .ko болтол хөрвүүлж, багийн гишүүн жинхэнэ кернелд ачаалсан. Ижил жагсаалтын API дээр ажилладаг C engine, python сервер, вэб UI хийж, графыг зөвхөн engine-ийн бодит төлвөөс зурсан.

Туршилт. make test нь 4 C тест, 9 сценарийн бүлэг, 15 HTTP тестийг ажиллуулдаг. Бүгд санах ойн болон тодорхойгүй үйлдлийн алдааг барьдаг хэрэгсэлтэй (AddressSanitizer, UndefinedBehaviorSanitizer) ажиллана. Мөн make module хоёр модулийг жинхэнэ кернелийн header-тэй хөрвүүлсэн (8.7). Багийн гишүүн тэдгээрийг өөрийн машин дээр insmod-оор ачаалж, dmesg-ийн гаралтыг авсан (8.8).

Гол үр дүн. Бүх тест амжилттай (All available tests passed.). Номын 4 өнгө, Collatz 27 (112 зангилаа), 837799 (525 зангилаа) зөв гарсан. ASan ба kmalloc == kfree бүртгэлээр shim тестэд санах ойн алдагдал илрээгүй. 1,254 байрлалд санах ойн алдааг зориудаар үүсгэж, 5,000 санамсаргүй үйлдлийг энгийн массив загвартай харьцуулж шалгасан. Номын жишээнд violet өнгийн ногоон, цэнхэр утга солигдсон байсан тул зөв утгыг (138, 43, 226) ашигласан. Жинхэнэ кернел дээр өнгөний 4 мөр, Collatz 27-ийн 112 утга (оргил 9232) shim-ийн үр дүнтэй таарсан.

Нэмэлт нотолгоо ба хязгаар. 2026-11-25-нд шинэчилсэн модулиудыг Arch Linux 7.3.4-arch1-2 дээр хоёр удаа ачаалж, зайлуулсан. Хоёр удаад color_list: freed 4 nodes, collatz: freed 112 nodes гарсан (8.8). Өмнөх хувилбарыг II-4-1 Ubuntu дээр, IV-2-1 Xubuntu дээр ачаалсан. IV-2-7 Ubuntu sandbox-д хөрвүүлсэн (8.9). Шинэчилсэн хувилбарын анхдагч start=25, буруу start=0, ENOMEM, kmemleak/slabinfo болон 200 удаагийн ачаалж/зайлуулах давталтыг бодит кернелд шалгаагүй. AI ашиглалтыг 5.8-д тайлбарлав.

1. Удиртгал

1.1 Зорилго

Кернел өөрийн өгөгдлийн бүтцийг өөрөө удирддаг. Linux «дугуй хоёр холбоост жагсаалт»-ыг өргөн хэрэглэдэг: элемент бүр өмнөх болон дараагийн элементээ мэддэг, сүүлийн элемент нь эхнийхтэйгээ холбогдсон. Бидний зорилго энэ жагсаалтыг номын даалгаврын дагуу хэрэгжүүлж, үйлдэл бүрийн дараа холбоос (заагч) юу болдгийг нүдээр харуулах явдал юм.

1.2 Ач холбогдол

Linux процессын жагсаалт, ажлын дараалал, санах ойн удирдлагад ийм жагсаалтыг хэрэглэдэг. Үүнийг ойлговол кернелийн код унших үндэс болно. Заагчийн алдаа кернелд хамгийн аюултай алдаа тул холбоосыг тусгай шалгагчаар болон дээрх хэрэгслүүдээр шалгасан.

3. Онолын үндэс

3.1 Дугуй хоёр холбоост жагсаалт

Жагсаалтын элемент бүр өөрийн өгөгдөл болон хоёр заагчтай: next нь дараагийн элементийг, prev нь өмнөх элементийг заана. Сүүлийн элементийн next нь жагсаалтын толгойг заадаг тул жагсаалт тойрог үүсгэнэ. Иймээс элемент нэмэх, устгахад зөвхөн түүний хоёр хөрш өөрчлөгдөнө. Харин тодорхой утгыг хайхад элементүүдийг дарааллаар нь шалгана.

3.2 Linux-ийн арга

Linux өгөгдлийн бүтцийн дотор struct list_head гэсэн жижиг хэсгийг шигтгэдэг. Тиймээс нэг жагсаалтын код ямар ч бүтэц дээр ажиллана. Жагсаалтын хэсгээс бүтцийн эхлэлийг list_entry олно. Үйлдлүүдийн хугацааг хүснэгт 2-т харуулав: O(1) гэдэг нь жагсаалтын уртаас хамаарахгүй, O(n) гэдэг нь уртад хувь тэнцүү гэсэн үг.

3.3 Collatz дараалал

Эерэг бүхэл n-ээс эхэлж, n тэгш бол n/2, сондгой бол 3n+1 болгон n = 1 болтол үргэлжилнэ. Дарааллын урт урьдчилан мэдэгдэхгүй тул жагсаалтад хадгалахад тохиромжтой. Утга хурдан өснө: 837799-ээс эхлэхэд 525 зангилаа үүсэж, оргил нь 2,974,984,576 болдог бөгөөд энэ нь 32 битийн тэмдэгтэй бүхэл тооны (int32) дээд хязгаараас (2,147,483,647) их. 2,147,483,647-оос эхлэхэд оргил нь 1,235,346,792,567,892 хүрнэ. Тиймээс утгыг 64 битээр хадгалсан.

4. Системийн зохиомж

4.1 Бүтэц

Нэг үйлдэл дараах дарааллаар явагдана. (1) Хэрэглэгч UI дээр үйлдэл сонгоно. (2) Сервер командыг engine-д нэг мөр болгон өгнө. (3) Engine жагсаалтын API-г бодитоор дуудаж, нэг мөр JSON хариу өгнө. (4) UI графыг зөвхөн энэ хариунаас зурна. Командын хэлбэр, оролтыг Manual-ын 8.1.4-өөс, алдааны кодыг 8.1.8-аас үз.

4.2 Шалгалт ба алдаа

Engine үйлдэл бүрийн дараа холбоосыг шалгагчаар (kds_verify) шалгана: next ба prev хоёр харилцан таарч байх ёстой, урагш ба хойш тоолсон элементийн тоо адил байх ёстой. Алдаатай команд төлөв болон санах ойн тоолуурыг өөрчилдөггүй. Эвдэрсэн жагсаалтад ч engine гацахгүй, UI дээр улаан «?» тэмдэг гарна. Процесс дуусахад амьд зангилаа үлдсэн бол LEAK гэж бичиж, 3 гэсэн код буцаана.

5. Хэрэгжилт

5.1 Хэл ба орчин

C (-std=gnu11 -Wall -Wextra -Werror), GNU make, python3 (зөвхөн стандарт сан), цэвэр JavaScript ба SVG. Гуравдагч талын сан, framework, CDN, фонт ашиглаагүй. Үндсэн эх кодын мөрийн тоо: Linux header shim 96 (үүнээс list.h 38), shim-ийн үндсэн код 106, кернелийн модуль ба Kbuild 129, хөдөлгүүр 406, HTTP сервер 303, UI 546. Makefile 74, GPL-2.0 лицензийн эх 117, үндсэн тест 1,418, тусдаа CDP тест 323 мөр. Хэмжилтийн хамрах файлыг Хавсралт Б-д үзүүлэв.

5.2 Part I — color_list.c

Номын алхмыг дагасан: struct color дотор list_head шигтгэж, эхэнд 4 өнгийг kmalloc-оор аваад list_add_tail-ээр нэмж, printk-ээр хэвлэнэ; дуусахдаа list_del ба kfree-ээр чөлөөлнө. Номд violet өнгийн ногоон, цэнхэр утга struct-ийн талбарын дарааллаар (red, blue, green) андуурагдсан байсан тул зөв RGB (138, 43, 226)-г ашигласан.

5.3 Part II — collatz.c

start нь 1-ээс бага бол -EINVAL буцаана. Кернелд 64 битийн хуваалт хэрэглэдэггүй тул хоёрт хуваахыг value >>= 1-ээр хийсэн. Утга 64 бит халихаар бол -EINVAL, санах ой авч чадаагүй бол өмнө авсан бүгдийг чөлөөлж -ENOMEM буцаана.

Хоёр модульд алдааны зам болон __exit функц ижил *_free_all() туслах функцийг дуудна. MODULE_AUTHOR-ыг бүртгэж, <linux/errno.h>-ийг шууд оруулсан. Зайлуулахад color_list: freed N nodes эсвэл collatz: freed N nodes мөр гарна. Эдгээр мөрийг shim тест болон шинэчилсэн модулийн бодит кернелийн ажиллуулалтаар шалгасан (8.1, 8.8).

5.4 Shim

Shim нь кернелийн header файлуудын оронд ажилладаг жижиг давхарга. Үүнд list.h (Linux-ийнхийг хуулаагүй, номын дагуу өөрсдөө бичсэн), kmalloc/kfree (санах ойг тоолж, чөлөөлсөн санах ойг тусгай утгаар дарж, давхар kfree-г шууд илрүүлнэ), printk, санах ойн алдааг зориудаар үүсгэх функц орно. Модулийн эх файлууд #include <linux/…> гэж бичигдсэн тул тест тэднийг өөрчлөлтгүй оруулж shim-тэй, Kbuild нь мөн тэр файлуудыг жинхэнэ header-тэй хөрвүүлдэг.

5.5 Engine ба сервер

Engine нэг команд = нэг мөр хүлээн авч, нэг мөр JSON хариу өгнө. Сервер зөвхөн 127.0.0.1 дээр сонсож, нэг engine процессыг ашиглана; engine үхвэл дараагийн хүсэлтэд дахин асаана. Терминал дээр Ctrl+C дарахад сервер engine-ийн оролтыг хааж, engine өөрийн цэвэрлэгээ ба leak шалгалтаа хийгээд гарна. Энэ нь SIGINT-ийг «үл тоомсорлох» төлөвтэй өвлөсөн үед ч ажиллах бөгөөд үүнийг тусдаа тест шалгадаг.

Ирсэн Host толгой нь серверийн порттой 127.0.0.1 эсвэл localhost байх ёстой. Гадаад Host болон зөвшөөрөөгүй POST Origin-д HTTP 403 E_ORIGIN буцаана. Сервер 4 KiB-аас том хүсэлтийн биеийг хүлээж авахгүй. 8 MiB хүртэлх хэтэрсэн биеийг уншиж хаяад HTTP 400, Connection: close өгнө. Хүлээгдэж буй TCP холболтын дарааллын хэмжээг 128 болгосон (8.1).

5.6 UI

UI-д 4 таб (өнгө, Collatz, стек, дараалал), үйлдлийн форм, граф, санах ойн тоолуур, алхамчилсан түүх, алдааны мэдэгдэл бий. Граф нь user-space shim ашигладаг C хөдөлгүүрийн жагсаалтыг зурна. Ачаалсан .ko-ийн төлөвийг dmesg-ээр шалгана. «Хүссэн байт» нь амьд зангилаануудад kmalloc-оор хүссэн хэмжээний нийлбэр. Кернелийн slab-д жишээлбэл 24 байтын хүсэлт 32 байтын ангилалд орж болно.

Графад next нь тасралтгүй сум, prev нь тасархай сум. «Бүгдийг багтаах» товч буюу граф дээрх End нь өргөн ба өндрөөр нь тааруулна. Жижиг бичгийг томруулж, графыг чирж, эсвэл зангилааны хүснэгтийг нээж уншина. Collatz табд дараагийн утгын дүрмийг тайлбарласан. kmalloc/kfree тоолуур хөдөлгүүрийн ажиллаж эхэлснээс хойших дүнг харуулна. Дэлгэрэнгүйг гарын авлагын 8.1-ээс үз.

Дээрх шалгалтуудыг чөлөөлсөн зангилааны тоог хэвлэдэг freed N nodes мэдээллийг нэмэхээс өмнөх хувилбар дээр хийсэн. Шинэчилсэн хувилбарыг бодит кернел дээр шалгасан үр дүнг 8.8-р хэсэгт оруулсан.

Shim орчинд модулийн анхны тохиргоо амжилтгүй болсон үед ч exit функцийг дуудаж, freed 0 nodes гэсэн мэдээлэл зөв гарч байгаа эсэхийг тусад нь шалгасан.

Кернелийн логт гарч буй freed мэдээлэл нь модуль өөрийн жагсаалтаас хэдэн зангилаа чөлөөлснийг харуулдаг. Харин ASan болон kmalloc, kfree функцийн дуудалтын тоонд үндэслэсэн санах ойн шалгалтыг shim орчинд хийсэн гэдгийг анхаарах хэрэгтэй.

9. Хэлэлцүүлэг

9.1 Үр дүнгийн тайлбар

Программын зөв ажиллагаа. Бид жагсаалтын үйлдлүүд болон Collatz дарааллыг зөв хэрэгжүүлсэн эсэхийг шалгахын тулд Python дээр бичсэн бие даасан лавлагаа, массив загвар болон жагсаалтын холбоос шалгагчийг ашигласан. Эдгээрийн үр дүн engine болон кернел модулиудын үр дүнтэй тохирч байсан.

Санах ойн ашиглалт. Shim орчинд программыг хэвийн ажиллуулахын зэрэгцээ санах ой хуваарилах алдааг зориудаар үүсгэж туршсан. Аль ч тохиолдолд kmalloc болон kfree функцийн дуудалтын тоо тэнцүү байсан. Өөрөөр хэлбэл, туршсан нөхцөлүүдэд хуваарилсан санах ойг бүрэн чөлөөлж чадсан.

Бодит кернел дээрх ажиллагаа. color_list болон collatz модулийг Linux-ийн кернелд ачаалж шалгасан. Өнгөний жагсаалтын 4 мөр, Collatz дарааллын утгын тоо болон хамгийн их утга нь shim орчинд гарсан үр дүнтэй тохирсон. Дэлгэрэнгүй үр дүнг 8.8-р хэсэгт үзүүлсэн.

Номын жишээнд хийсэн засвар. Номын жишээг судлах явцад violet өнгийн ногоон болон цэнхэр өнгөний утга солигдсон байсныг анзаарч, өөрийн хэрэгжүүлэлтэд зассан.

Мөн Collatz дарааллыг 2,147,483,647 гэсэн утгаас эхлүүлж туршихад дарааллын хамгийн их утга 32 битийн бүхэл тоонд багтахгүй байгааг тогтоосон. Иймээс том утгуудтай ажиллахын тулд 64 битийн өгөгдлийн төрөл ашиглах шаардлагатай болсон.

9.2 Хязгаарлалт

Төслийн үндсэн шаардлагуудыг хэрэгжүүлж, олон төрлийн тест хийсэн боловч дараах шалгалт болон сайжруулалтууд үлдсэн.

Кернелийн шалгалт. Шинэчилсэн хувилбарыг бодит кернел дээр хоёр удаа туршихдаа өнгөний модуль болон 27-оос эхлэх Collatz дарааллыг шалгасан. Харин анхдагч start=25 болон буруу start=0 утгыг шинэ хувилбар дээр дахин туршаагүй. Мөн kmemleak, slabinfo ашиглан санах ойг хэмжих, модулийг 200 удаа ачаалж буулгах, санах ой хуваарилах алдааг зориудаар үүсгэх болон модулийн гарын үсгийн шаардлагыг бодит кернел дээр шалгаагүй.

Shim болон бодит кернелийн ялгаа. Хэрэглэгчийн орчинд хийсэн тестүүд нь бидний өөрсдийн бичсэн list.h файлыг ашигладаг. Харин жинхэнэ кернел модулиуд Linux-ийн үндсэн list.h файлыг ашигладаг.

Тиймээс shim орчин нь бодит кернелийн ажиллагааг бүхэлд нь орлохгүй. Санах ойн ачаалал, preemption, олон процессорын ажиллагаа болон printk-ийн логийн түвшнийг shim орчинд загварчлаагүй. Санах ой хуваарилах алдааг мөн хиймлээр үүсгэж шалгасан. Түүнчлэн shim-ийн kfree функц нь O(n) хугацааны төвөгшилтэй боловч төслийн 2048 хүртэлх зангилаатай жагсаалтад ашиглахад хангалттай.

Зэрэгцээ хандалт. Кернелийн жагсаалтын үндсэн бүтэц нь өөрөө түгжээний механизмгүй. Манай engine нэг процесс болон нэг түгжээ ашиглан ажилладаг тул олон хэрэглэгч зэрэг хандах зориулалттай серверийн систем биш юм.

Хөтөч болон үйлдлийн системийн дэмжлэг. Манай баг веб интерфэйсийн автомат тестийг Brave болон Chromium хөтөч дээр хийсэн. II-4-1 баг Firefox 147 дээр ажиллуулж шалгасан. Харин Safari хөтөч болон macOS, Windows үйлдлийн системийн үндсэн орчинд туршаагүй.

Loopback тест нь /proc/net/tcp файлаас мэдээлэл авдаг. Уг файл байхгүй тохиолдолд тестийг алгасдаг бөгөөд /proc/net/tcp6 байхгүй бол зөвхөн IPv4 холболтыг шалгана.

Веб интерфэйс. Олон зангилаатай жагсаалтыг дэлгэцэд багтааж харуулах үед бичиг болон зангилааны хэмжээ жижигэрдэг. Одоогоор зангилаануудыг бүлэглэж, хураангуй хэлбэрээр харуулах боломж байхгүй. Мөн хэрэглэгчийн сесс бүрийн kmalloc, kfree тоолуурыг тусад нь харуулдаггүй.

GitHub ашиглалт. Төслийн шинэчилсэн хувилбарт Tag болон Release үүсгээгүй. Шүүмжлүүлсэн хувилбарын гурван commit нэг GitHub бүртгэлээс орсон тул гишүүн бүрийн хийсэн ажлыг Git түүхээр тусад нь баталгаажуулах боломжгүй байна. Шүүмжлэгч багуудын санал болон тэдгээрт өгсөн дэлгэрэнгүй хариуг docs/IV-2-4_Review_Response.md файлд оруулсан.

9.3 Цаашдын ажил

Цаашид шинэчилсэн Collatz модулийг start=25, start=0 болон бусад захын утгуудаар бодит кернел дээр дахин шалгах шаардлагатай. Мөн санах ой хуваарилах алдаатай нөхцөл болон модулийг олон удаа ачаалж буулгах үед санах ой бүрэн чөлөөлөгдөж байгаа эсэхийг kmemleak, slabinfo ашиглан нарийвчлан шалгахаар төлөвлөж байна.

Веб интерфэйсийн хувьд олон зангилаатай жагсаалтыг илүү ойлгомжтой харуулахын тулд зангилаануудыг бүлэглэж, шаардлагатай үед дэлгэж харах боломж нэмэх нь зүйтэй. Үүнээс гадна хэрэглэгчийн сесс бүрийн санах ойн тоолуурыг тусад нь харуулдаг болгох боломжтой.

10. Дүгнэлт

Энэхүү бие даалтын хүрээнд бид Operating System Concepts номын Part I болон Part II хэсэгт өгөгдсөн даалгаврын дагуу Linux-ийн холбоост жагсаалтын бүтцийг ашигласан хоёр кернел модуль боловсруулсан.

Эхний модуль нь дөрвөн өнгөний мэдээллийг хадгалдаг бол хоёр дахь модуль нь өгөгдсөн тооноос эхлэн Collatz дарааллыг үүсгэдэг. Эдгээрийг бодит кернелд ажиллуулахаас гадна эх кодыг нь өөрчлөхгүйгээр user-space shim орчинд хөрвүүлж, автомат тест хийх боломжтой болгосон.

Мөн зөвхөн кернелийн логоос жагсаалтын ажиллагааг ойлгоход хүндрэлтэй байдаг тул интерактив веб интерфэйс бүтээсэн. Уг интерфэйс нь жагсаалтын зангилаанууд хоорондоо хэрхэн холбогдож байгаа, элемент нэмэх болон хасах үед холбоосууд хэрхэн өөрчлөгдөж байгаа, санах ой хэрхэн хуваарилагдаж, чөлөөлөгдөж байгааг дүрслэн харуулдаг.

Shim орчинд Collatz дарааллын 7 лавлагаа, санах ой хуваарилах алдаа үүсгэх 1,254 байрлал болон зориудаар эвдсэн 10 жагсаалтыг шалгасан.

2026 оны 11-р сарын 25-нд бодит кернел дээр хоёр модулийг ачаалж, үр дүнг лавлагаатай харьцуулсан. Өнгөний жагсаалт 4 мөр хэвлэсэн бөгөөд Collatz дарааллыг 27-оос эхлүүлэхэд нийт 112 утга гарч, 77-р индекс дээр 9232 гэсэн хамгийн их утгад хүрсэн. Модулиудыг буулгахад freed 4 nodes болон freed 112 nodes гэсэн мэдээлэл гарсан.

Түүнчлэн II-4-1 баг төслийн өмнөх хувилбарыг Ubuntu дээр ажиллуулж, Collatz дарааллын 25, 27 болон буруу 0 утгыг бие даан шалгасан.

Эдгээр туршилтаас үзэхэд төслийн үндсэн шаардлагуудыг амжилттай хэрэгжүүлсэн гэж дүгнэж байна. Гэхдээ шинэчилсэн хувилбарын зарим захын тохиолдол, бодит кернелийн санах ойн алдагдал болон олон удаагийн ачаалах, буулгах үйлдлийг цаашид нэмэлтээр шалгах шаардлагатай.

Энэ ажлыг хийснээр бид Linux кернелийн өгөгдлийн бүтэц, хоёр чиглэлт холбоост жагсаалт, заагчийн ажиллагаа болон санах ойг зөв удирдахын ач холбогдлыг илүү сайн ойлгож авсан. Мөн кернелийн түвшний программыг хэрхэн тестлэх, алдаа гарсан үед санах ойг хэрхэн зөв чөлөөлөх талаар практик туршлага хуримтлуулсан.
